# Concord v0.12.6

## A Task name states what will be true

Nothing said what a name should carry, so names were drawn from whatever was
easiest to write: the finding that opened the line, the tool being touched, or
the activity about to start. Such a name binds nothing, and the work outgrows
it while every prose reference in other Tasks and in frozen Phases keeps
pointing at it.

The shipped skill now says a name states what will be true once the Task is
done. A standing line that has no terminal state names its function instead,
correct for that shape and wrong for every other.

A new restrained scenario covers the case that matters most: when the
deliverable is not yet clear enough to name, report it and stop. Renaming later
keeps the permanent identity but leaves the earlier references pointing at a
name that no longer exists, which is the first class of drift this estate is
audited for. The caller owns the vocabulary of their own domain.
