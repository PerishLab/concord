# Concord v0.12.7

## 被拒的坐标现在自己回答

`concord.task.absent` 是操作者实际撞得最多的一条拒绝，而它只说了「没找到这个名字」。
猜错名字的 agent 无从得知**哪些名字存在**，于是接着猜：某个会话三分钟内撞出二十二次，
且是同秒成批发出的。

四种拒绝现在带上调用方本就需要的坐标：

- `concord.task.absent` 在 `details.tasks` 带活跃身份，附 `active` 与 `retired` 计数；
  域本身不存在时改带 `details.domains`。
- `concord.task.ambiguous` 带相撞的身份。
- `concord.domain.absent` 带现存的域。

列表**只列活跃身份**。退休名字仍可解析，但把它们一起排序会把每一个活跃名字挤到上限之外；
`retired` 计数交代列表略去了什么，`active` 与列表长度之差交代上限在哪里截断。

四个站点此前逐字复制同一句拒绝，现在共用一个 `World::absent`，details 因此四处同时具备。

## 测试不再写进操作者的观测报告

`cargo test` 从操作者的 shell 继承了 `CONCORD_LOCUS_*`，于是每轮测试都把自己的 fixture
追加进那个正在使用的报告文件。**记录到的调用有四分之一、失败有百分之四十四是测试伪造的**，
而且恰好集中在操作者会去研究的那几种拒绝上。

测试现在统一经一个共享座位启动二进制：座位清掉每一个继承来的 `CONCORD_` 变量，
并把报告重定向进 fixture。**重定向才是承重的那一半** —— 静默可以被忘记，
但重定向过的报告到不了操作者的文件。一条守卫测试会拒绝任何绕过座位启动二进制的测试。

Plumb lock 推进到 0.20.0。
